# 🎮 Agent Rules v2 사용 가이드

이 문서는 `agent_rules_v2` 시스템을 100% 활용하기 위한 **사용자 매뉴얼**입니다.

## 1. 🚀 세션 시작 (Booting)
새로운 대화를 시작할 때, 가장 먼저 다음 명령어를 입력하여 에이전트를 깨우세요.

> **추천 프롬프트:**
> "시스템 부팅해줘. `CLAUDE.md` 실행."

**효과:**
- 에이전트가 `tech_stack.md`를 읽어 프로젝트 환경을 파악합니다.
- 불필요한 탐색 비용(파일 읽기 토큰)을 절약합니다.
- 즉시 작업 가능한 상태가 됩니다.

## 2. 🎭 역할 지정 (Role Switching)
작업의 성격에 따라 명확한 모자를 씌워주세요.

### 🛠️ 구현이 필요할 때
> "Implementer 모드로 전환해. [기능명] 구현 시작."
- **효과**: `roles/implementer.md` 로드. 코드 품질, 컴포넌트 재사용성에 집중.

### 🏗️ 설계나 구조 변경이 필요할 때
> "Architect 모드로 전환해. 리팩토링 계획 세워줘."
- **효과**: `roles/architect.md` 로드. 전체 구조, 의존성, 기술 부채에 집중.

## 3. 🧠 지식 확장 (Teaching)
에이전트에게 특정 코딩 스타일을 강제하고 싶다면 `.context/patterns/`에 파일을 추가하세요.

**예시: `api_pattern.md` 만들기**
```markdown
# API 작성 규칙
- 모든 API는 `src/shared/api`에 위치해야 한다.
- 에러 처리는 `try-catch` 대신 `Result` 타입을 사용한다.
```
이렇게 파일을 만들어두면, Implementer가 코드를 짤 때 이 규칙을 자동으로 참조합니다.

## 4. 🧹 유지보수 (Gardening)
프로젝트 설정이 바뀌면 에이전트에게 업데이트를 지시하세요.

> "Next.js 버전 올렸어. `tech_stack.md` 업데이트해줘."

이것만 지키면 에이전트는 영원히 늙지 않는 최신 상태를 유지합니다.
